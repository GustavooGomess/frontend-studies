## 1. Por que gerenciar um projeto Front-End?

Projetos Front-End podem crescer rapidamente. Sem planejamento, aparecem problemas como:

| ❌ Sem gestão | ✅ Com gestão |
|---|---|
| Tarefas esquecidas | Responsabilidades claras |
| Requisitos confusos | Prioridades definidas |
| Retrabalho | Entregas incrementais |
| Conflitos no Git | Acompanhamento do progresso |
| Atrasos | Redução de retrabalho |
| Problemas de integração | |
| Dificuldade para acompanhar o progresso | |

## 2. Gestão de Projetos Front-End

Gerenciar projetos Front-End significa **organizar pessoas, tarefas, tecnologias e prazos** para transformar uma ideia em uma aplicação funcional.

Durante o projeto, as decisões precisam ser **planejadas, acompanhadas e ajustadas** para garantir entregas contínuas e alinhadas aos objetivos definidos.

---

## 3. Gestão de Requisitos

Um projeto normalmente começa com uma **ideia**, que precisa virar **requisitos claros** e, depois, ser organizada em um **backlog**.

Em seguida, as atividades são priorizadas, desenvolvidas, revisadas, testadas e disponibilizadas aos usuários por meio de um processo estruturado.

```
Ideia → Requisitos → Backlog → Priorização → Desenvolvimento → Revisão → Testes → Entrega
```

---

## 4. Requisito, História e Tarefa

Do mais amplo ao mais específico:

| Nível | Exemplo |
|---|---|
| **Requisito** | O sistema deve permitir o gerenciamento de tarefas |
| **User Story** | Como usuário, quero criar uma tarefa |
| **Tarefas** | Criar formulário · Criar componente · Validar campos · Integrar API · Criar testes |

---

## 5. Gestão do Backlog

O **backlog** reúne funcionalidades, melhorias, correções e outras atividades necessárias para desenvolver e evoluir um produto.

Os itens podem receber **prioridades diferentes**, permitindo que a equipe concentre esforços primeiro nas funcionalidades mais importantes.

---

## 6. Gestão de Prioridade e Estimativa

- **Priorização:** ajuda a equipe a decidir quais funcionalidades desenvolver primeiro, considerando objetivos, necessidades e restrições.
- **Estimativas:** ajudam a equipe a compreender a complexidade relativa das atividades antes de assumir um conjunto de tarefas.

---

## 7. Definition of Done (DoD)

Estabelece os **critérios necessários para considerar uma tarefa realmente concluída** dentro de um projeto.

Exemplos de critérios:

- [ ] Código implementado
- [ ] Testes realizados
- [ ] Revisão concluída
- [ ] Responsividade verificada
- [ ] Integração realizada

---

## 8. Scrum

O Scrum é um **framework ágil** usado para desenvolver produtos complexos de forma incremental, permitindo inspeção frequente, adaptação e entregas contínuas.

No desenvolvimento Front-End, ele ajuda a:

- Organizar requisitos
- Priorizar funcionalidades
- Planejar **Sprints**
- Acompanhar o trabalho realizado pela equipe
